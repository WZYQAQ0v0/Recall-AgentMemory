# Recall 0.3.0 验收合同

本文件规定可分发代码包的验收范围。自动测试、安装配置、服务运行和真实 AI 客户端采集分别记录，不互相代替。

## 必须验证的行为

| 范围 | 验证方式 | 通过标准 |
| --- | --- | --- |
| 本地索引 | 合成 Codex、Claude 和事件记录 | 可搜索中文及技术标识、原文完整、增量去重、镜像身份正确 |
| 机密模式处理 | 含虚构密钥的记录 | 索引及导入文件不保存匹配到的密钥模式 |
| 安装与升级 | 假用户目录和隔离前缀 | 数据、笔记、收藏、来源配置保留；失败恢复旧代码和服务 |
| 来源和事件 | 带外部事件的假客户端配置 | 添加一次自己的事件，重复安装不重复，卸载保留外部条目 |
| 端口和服务身份 | 同时运行不同测试实例 | 避开已占用端口，只停止当前安装拥有的服务 |
| 文件夹分发 | 安装后删除原源码副本 | 固定入口能重新启动和自检 |
| 特殊路径 | 带空格、中文、百分号的路径 | 安装、捕获、索引、管理命令正常 |
| 真实启动项 | 对应系统隔离用户启动登记 | 由 OS 启动正确进程，停止后能按登记再次启动，卸载后清理 |
| 会话跳转 | 真实卡片到客户端及单元测试 | 原生 ID 定位；镜像明确标记；不发送问题；无入口时说明原因 |
| 浏览器 | 实际访问安装地址 | 搜索、详情、来源状态、导入及窄屏布局可用 |
| 清洁发布 | ZIP 和逐文件清单 | 只有源码、文档、虚构示例和测试，没有作者数据 |

## doctor 的含义

ready=true 表示运行时、包完整性、当前服务和已登记集成没有检测到错误。pipeline_smoke.passed=true 证明合成 JSON 事件可经过实际 helper 进入索引、搜索和摘要；real_client_callback=false 明确说明这不是客户端端到端验收。

trae_live_events.observed=true 表示安装后在实际 data 目录观察到当前安装 helper 捕获过消息。它不证明完整历史已迁移，也不证明客户端所有消息字段都能提供。未观察到时为 awaiting_client_callback。

没有找到本地历史或首轮扫描仍运行，会作为 warning 返回，不伪造历史或完成状态。部分来源文件不可读会保留 index.errors，便于定位权限或格式问题。

## 平台支持声明

macOS 是本版本的主要实测目标。Linux 有 systemd 用户服务与桌面 autostart，Windows 有当前用户 Startup 适配；描述符与公共安装链路可以做隔离自动测试。Linux/Windows 的整机启动、官方运行时安装、浏览器和真实客户端采集，需要在相应系统实际验证。macOS 验收结果不能推断其他系统已通过。

权限授权、企业策略、缺失 AI 客户端和 Trae 加密历史均属于环境条件或能力边界。交付报告应保留这些具体状态。
